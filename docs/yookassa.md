# ЮKassa

Поддерживаются разовая покупка бессрочной лицензии и подписки на месяц/год,
включая оплату за места. Stripe продолжает работать независимо.

## Настройка

1. Примените миграцию `20261031_yookassa.up.sql` штатным механизмом проекта.
2. Откройте **Настройки → ЮKassa → Использовать эти настройки**.
3. Укажите ID магазина, секретный ключ, тестовый режим и код НДС. Нажмите **Сохранить**.
   Для шифрования ключа нужен `RELEASE_KEY_ENCRYPTION_KEY`, как для пароля SMTP.
   Пустое поле ключа сохраняет прежнее значение; отдельная кнопка удаляет его.
4. В кабинете ЮKassa настройте URL `https://YOUR_DOMAIN/api/v1/webhook/yookassa`
   для событий `payment.succeeded` и `payment.canceled`.
5. Для автоплатежей подключите эту возможность в ЮKassa.
6. В тарифе задайте цену ЮKassa в рублях. Для подписки выберите месяц или год.
   Нулевая цена отключает ЮKassa для тарифа. Для тарифов с оплатой за места цена
   указывается за одно место.

Настройки из админки применяются без перезапуска. Режим **Использовать переменные
окружения** читает `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, `YOOKASSA_TEST_MODE`
и `YOOKASSA_VAT_CODE`; это также режим по умолчанию. В режиме базы данных
реквизиты не смешиваются с переменными окружения. Полное отключение прекращает
создание и обработку платежей, включая автопродления.

Код НДС `0` отключает передачу чека: чек формируется отдельно. Ненулевой код
передаётся в чеке с предметом расчёта `intellectual_activity` и способом
`full_payment`. Эти параметры рассчитаны на продажу программных лицензий.
При другой номенклатуре необходимо адаптировать состав чека.

## Оплата и продление

Ссылка `/pay/<checkout_id>` открывает форму с ценой и email. Для подписки
покупатель явно соглашается на сохранение способа оплаты и регулярные списания.
Если тариф также содержит цену Stripe, ссылка с `?provider=stripe` использует Stripe.

Лицензия выдаётся только после проверки платежа через API ЮKassa, включая сумму,
валюту, магазин, тестовый режим и идентификатор заказа. Возврат покупателя на
сайт сам по себе не подтверждает оплату. Webhook и фоновая сверка используют
одну запись заказа и не выдают вторую лицензию.

Подписка сохраняет цену и период первой покупки. Изменение цены тарифа не меняет
существующие подписки. При смене магазина или тестового режима старые заказы и
подписки перестают обрабатываться до восстановления исходных настроек.

Обработчик раз в минуту создаёт списания для наступивших периодов и проверяет
незавершённые платежи. Для повторных запросов сохраняются тело запроса и ключ
идемпотентности. После неопределённого результата создания платежа повторное
создание прекращается через 23 часа: оператор должен сверить заказ с ЮKassa,
чтобы не списать деньги повторно после окончания окна идемпотентности.

В личном кабинете покупатель может отключить автопродление. Уже отправленный
платёж может завершиться; отмена предотвращает последующие списания. Оплаченный
доступ сохраняется до конца периода. Если способ оплаты не сохранился или
автоплатёж отклонён, автопродление отключается; повторные списания не выполняются.

## Границы реализации

- Пробный период, смена тарифа/числа мест с перерасчётом, обновление платёжного
  метода и отдельное продление периода обновлений через ЮKassa не реализованы.
- Возвраты выполняются в кабинете ЮKassa; изменение лицензии после возврата
  выполняется администратором вручную. Webhook возвратов не обрабатывается.
- Ручное изменение тарифа, количества мест или срока лицензии останавливает
  создание новых списаний до согласования записи подписки с изменёнными условиями.
- Перед использованием нужно самостоятельно проверить миграцию, тестовую оплату,
  выдачу лицензии, повторные уведомления, автопродление и отмену в тестовом магазине.
